## Decisions (design settled 2026-11-21, nothing built yet)
- D1: Follow the USER's flow, not Gemini's simultaneous phases: turn-based draft. For round = 1..2 (DRAFT_ROUNDS), for each player in seat order: chooser picks 1 of 3 powers (12 s, auto option 1) -> everyone else votes among that power's 3 nerfs (8 s, live tallies to voters only, target sees suspense screen, target's votes rejected) -> 2.5 s reveal to all -> next turn. Each player ends with 2 powers + 2 nerfs. Why: user's words ("Player chooses superpower out of three options -> Remaining vote on nerf ... -> Nerf revealed ... next draft. maybe two superpower drafts per person"). Rejected: Gemini's separate 1v1 blind counter-pick mode; with one voter the same vote code IS a blind counter-pick, so one code path covers 1v1 and FFA.
- D2: Skip building the arena lock and a separate cleanup routine: they exist (F2, F3). Only add: AbilityService.Unequip still called in _cleanup; character reload is the reset. Registry hooks: OnApply(player, character) only; OnRemove skipped because the character is replaced each round (shortcut comment). Rejected: manual stat resets (duplicates LoadCharacter).
- D3: Draft runs at the table while players stay seated (before MatchInstance). TableManager: `local loadouts = Draft.Run(players)`; nil = abort (fewer than 2 left) -> back to table, lock released. MatchInstance.new gets loadouts {[Player]: {powers:{string}, nerfs:{string}}} and calls AbilityService.Equip(p, character, loadout) instead of TEST_ABILITY.
- D4: 4 powers, not 3, so the 2nd draft still offers 3 options (a player never gets the same power twice; different players may). Add Leap (passive, higher jump) with nerfs Brittle (MaxHealth -20), Clumsy (WalkSpeed -4), Tired (jump only slightly higher).
- D5: Stats are relative deltas so 2 powers + 2 nerfs stack sanely: Juggernaut MaxHealth +50 (150) and character:ScaleTo(1.15); GlassCannon MaxHealth -70; Sluggish WalkSpeed -6; HeavyGravity JumpPower -15. Set hum.UseJumpPower = true before changing JumpPower (F1). Heal to MaxHealth after applying.
- D6: Active powers by key: PhaseDash Key "Q", Shockwave Key "E" (no collision). Client sends Ability:FireServer(keyName "Q"/"E"); server validates string, finds the equipped power with that Key, checks cooldown/alive/same character. PhaseDash: server FireClient(p, "Blink", distance, blind) -> client raycasts forward (move direction or look) and moves root CFrame (distance 20, ShortCircuit 10); BlindDash -> client dark overlay 1.5 s; Fragile -> server Health = max(1, Health-10) (never 0, see table-lobby D4). Shockwave: server finds foes within 15 studs, FireClient(foe, "Knockback", velocity) (client owns its physics; shortcut: an exploiter can ignore knockback); neon sphere VFX server-side; SelfKnockback -> knock the user back too; Exhaustion -> WalkSpeed -8 for 2 s (restore only if same character); Telegraphed -> red warning sphere then fire after 1.5 s (Gemini said 3 s; too long for 7-stud sword range, tunable constant).
- D7: Registry = ReplicatedStorage.AbilityRegistry (ModuleScript, --!strict): Powers[id] = {Id, Name, Description, Cooldown, Key?, NerfPool={3 ids}, OnApply}, Nerfs[id] = {Id, Name, Description, OnApply}. Client only reads Name/Description. Assert self-check: every NerfPool has 3 ids that exist in Nerfs.
- D8: One new RemoteEvent Remotes.Draft. Server -> client: FireClient(p, state) where state = {phase "pick"|"vote"|"reveal"|"done", chooser name, power name, options {name, desc}? (only to the chooser in pick, only to voters in vote), tallies? (voters only), endsAt = workspace:GetServerTimeNow()+t, summary lines}. Client -> server: ("Pick", i) / ("Vote", i); server checks phase, sender role, i is integer 1..3. Vote ends at timeout or when every present voter has voted. Ties incl. 0 votes: random among top. Chooser leaves mid-turn -> skip; < 2 players left -> abort.
- D9: HUD: server sets Player attribute "Loadout" (text like "Q PhaseDash (Fragile) | Juggernaut (Sluggish)"); new LocalScript DraftClient shows the draft screen and the loadout line. Move the E/Dash client code out of TableClient into DraftClient (or keep in TableClient, edit lines 104-118).

## Decisions
- D1: Web prototype used plain JS instead of React + Tailwind. Why: one small page, no build step, same result. Rejected: React/Tailwind via CDN (extra weight for no gain).
- D2: Panel is open to all players, lobby only; toggles apply to the real character through AbilityService.Equip. Why: the user's answers, 2026-11-25 22:55. Rejected: Studio-only gate; readout only.
- F3 SETTLED: Match state signals. MatchInstance sets the player attribute Fighting (true = standing, false = knocked out, nil = not in a round) and Arena. AbilityService.Equip sets the Loadout attribute, and TableManager clears it after the series. Tables publish InMatch on their model. During the map vote or draft, players sit at a table with Fighting = nil. MatchInstance calls LoadCharacter + Equip every round, so a test loadout can't leak into a match. Source: script_read of MatchInstance + TableManager, 2026-11-25 22:55.
- F4 SETTLED (re-checked 2026-11-25 22:57, AbilityService line 60 + MeleeController 181/193, MovementController 26, MoveFxRelay 28 all gate on Fighting == true): In the lobby, R/E actives won't fire, because AbilityService `standing()` needs Fighting == true. Passive stat powers (Juggernaut, Leap and the stat nerfs) do work. Options: a TestMode attribute that standing() also accepts (lobby only), or show the actives as "match only" in the panel. Decided in D3.
- D3: Lobby actives work through a TestMode player attribute. AbilityService `standing()` becomes `Fighting == true or (Fighting == nil and TestMode == true)`. Why: user picked it, 2026-11-25 22:58. Rejected: greying out R/E as "match only". Known effect: a tester's Shockwave can push other lobby testers (only players who are equipped and standing).
- F5 SETTLED: R/E input is sent by DraftClient (lines 342-349) with no client-side Fighting gate, and DraftClient applies Blink/Knockback. So only the server `standing()` needs TestMode. Melee (MeleeController 181/193) and MovementController/MoveFxRelay stay gated on Fighting (not powers, leave them). MatchInstance._combat: LoadCharacter, then Fighting=true, then Equip (lines 152-162). Source: script_grep + script_read, 2026-11-25 22:58.
- D4 (design, not built): TestArena server rules. Payload (powerId: unknown, nerfs: unknown). powerId nil = reset (LoadCharacter only). Reject when Fighting ~= nil, humanoid seated, Loadout ~= nil while TestMode ~= true (a series is running), or under 1 s since the last request. After Equip, set TestMode = true. On CharacterAdded with TestMode true: clear TestMode and Loadout and Unequip (a lobby respawn resets cleanly; TestArena's own LoadCharacter runs this first, then re-equips). Also clear TestMode when Fighting changes or the humanoid sits. Why: Equip sets Loadout, so the old "Loadout ~= nil" rule alone would block a second test.
- F6 SETTLED: Built 2026-11-25 23:09: AbilityService standing() (lines 59-65) now passes when Fighting == true, or Fighting == nil and TestMode == true. Place saved v99. Other facts: Remotes has HostAction, Ability, Draft, MeleeRequest, MoveFx, Auction (no TestLoadout yet). The Loadout attribute is only a HUD string (DraftClient 334/338) and is cleared by TableManager 152. Describe() pairs nerf i with power i, so a 1-power / 3-nerf test shows only the first nerf on the HUD (cosmetic). Source: script_read + execute_luau, 2026-11-25 23:09.
- D5 (design, refines D4): Assume deferred signals. TestArena's own LoadCharacter fires CharacterAdded later, so a naive handler would clear TestMode after we set it. Fix: store testChar[player] = the new character after LoadCharacter; the CharacterAdded handler skips that character. For any other character: if TestMode == true, clear TestMode, and clear Loadout only when Fighting == nil. Never call Unequip there (it could run after MatchInstance's Equip and wipe a match loadout; the old equip is already dead because standing() checks p.Character). Clear TestMode on Humanoid.Seated. Why: avoids races with MatchInstance (LoadCharacter, Fighting=true, Equip). Rejected: Unequip on CharacterAdded (D4's wording).
- F7 SETTLED: Built 2026-11-25 23:12, place saved v101. ReplicatedStorage.Remotes.TestLoadout (RemoteEvent). ServerScriptService.TestArena (Script, --!strict) follows D4 + D5: 1 s rate limit, rejects Fighting ~= nil / seated / non-test Loadout; checks powerId in Registry.Powers and nerfs (max 3, no repeats, in NerfPool); LoadCharacter, testChar[p] = new char, Equip, TestMode = true; nil powerId = clear + LoadCharacter. StarterPlayerScripts.TestArenaClient (LocalScript): "TEST ARENA" toggle on the left edge (hidden when Fighting ~= nil), 620x440 panel in the web colours, power column (sorted ids), nerf toggles, MAX HP / WALK SPEED / JUMP POWER cards with +/- vs 100/16/50, APPLY / RESET, log (keeps ~60 lines, logs TestMode changes). No console errors after the line-197 fix. Screenshot showed the panel as designed. NOT yet tested: real mouse clicks on power/nerf buttons, R/E actives firing in the lobby, Seated / Fighting clearing TestMode. Source: execute_luau + screen_capture, 2026-11-25 23:13.
